## ✅ XSS verdict: you’re safe *with this config*

With `react-markdown` v10 and **no `rehype-raw`**, raw HTML in the source is **not** interpreted as HTML. It’s treated as text nodes, so things like `<script>` or `<img onerror=...>` won’t execute. Your current rendering:

```tsx
<ReactMarkdown>{chat.content}</ReactMarkdown>
```

…is the safe default. So the big “public internet” footgun is not present. Good.

### The one “don’t accidentally do this later” warning

If in a future iteration you add:

* `rehypeRaw` / `rehype-raw`
* or allow HTML via `skipHtml={false}` / custom rehype pipeline

…then you *do* need sanitization (DOMPurify or `rehype-sanitize`). So my advice is: **leave a code comment** above the component to prevent future-you from “just enabling HTML real quick.”

Example:

```tsx
// Security: Do NOT add rehype-raw without sanitization (XSS risk).
```

That comment pays dividends.
